# Contributing

Use Python 3.12, create a virtual environment, and install `.[dev,analytics]` with `requirements.lock` as constraints. Keep changes focused, use synthetic fixtures and run the relevant tests before opening a pull request.

Changes to ingestion or case state need tests for failure behavior as well as successful behavior. Changes to consumption calculations should address resets, missing intervals and the first observation. Changes to dbt models need both DuckDB and PostgreSQL validation when available. Do not silently update the benchmark labels to make a new detector pass.

Run `ruff check .`, `ruff format --check .`, `pytest -q`, `aquawatch analytics`, and `npm run test:browser` as appropriate. The browser suite uses a disposable database. PostgreSQL tests require the exact database name `aquawatch_test` and drop its operational tables; never point them at another environment.

Power BI source is generated by `scripts/build_powerbi.py`. Update the generator if report changes should be reproducible, and verify the result in Desktop. Keep private paths and `.pbi` caches out of commits.

Never add real customer information, credentials, claimed business savings or unverifiable benchmark results. Record material tradeoffs and limitations in the docs. External code requires a compatible license and explicit attribution.
