# Publication and verification — 18 September 2026

The source is public at [Moundirhzr2/aquawatch](https://github.com/Moundirhzr2/aquawatch). This publishes the source and documentation; the web application is still a local demonstration.

## Verified results

- The first GitHub run passed Linux application/browser checks, PostgreSQL checks and the complete Docker integration job. Windows exposed a Python installation layout issue: the analytics command looked for dbt beside python.exe. It now invokes `python -m dbt.cli.main` using the active interpreter, and the full analytics pipeline also passed locally after this fix.
- [Initial workflow evidence](https://github.com/Moundirhzr2/aquawatch/actions/runs/35387494061). Its overall result is a failure because of the Windows issue; individual passing jobs remain evidence for those environments.
- [Corrected workflow](https://github.com/Moundirhzr2/aquawatch/actions/runs/35387808735). Consult this run for its final status.
- Native Power BI refresh and DAX validation passed again on 18 September: 14 measures, seven table counts, four district groups and 90 date groups agree with the source CSVs. A temporary validation model was removed afterward.
- The corrected `Flagged invoices` measure returns **0** for an empty selection, **0** for the unflagged invoice INV-0001 and **1** for the flagged invoice INV-0015. This was executed in the native model engine. No new screenshot/rendering check is claimed.
- OSV checked 85 pinned Python/npm dependencies on 18 September: no matching advisories. This does not cover operating-system packages or establish absence of vulnerabilities.
- The candidate source files passed structured-file parsing and checks for known local credentials, common credential signatures and private paths. Runtime data, credentials and Power BI caches are excluded from Git.

## Main branch protection

The GitHub API confirmed protection after configuration. Pull requests and all four workflow jobs are required. Branches must be up to date; conversations must be resolved. Force pushes and deletion are disabled. Administrators are subject to the same rules. Zero external approvals are required so the sole maintainer can merge a passing pull request.

Later changes should follow this workflow rather than push directly to main. See [CONTRIBUTING.md](../CONTRIBUTING.md).

## Scope
